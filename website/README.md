# Notchly website

The official site for Notchly: a dark, fast product site with a live React replica of the
island, a download system wired to GitHub Releases, and a page per job (features, download,
changelog, privacy).

Vite · React 19 · TypeScript (strict) · Tailwind CSS 4 · shadcn/ui · Motion · Lenis ·
React Router · Shiki · react-markdown.

## Run it

Requires Node 20.19+ (24 recommended).

```bash
cd website
npm install
npm run dev          # http://localhost:5173
```

| Script                            | What it does                                                               |
| --------------------------------- | -------------------------------------------------------------------------- |
| `npm run dev`                     | Dev server with hot reload (client-rendered).                              |
| `npm run build`                   | Typecheck, build, then **prerender every route** to static HTML (`dist/`). |
| `npm run preview`                 | Serve `dist/` locally.                                                     |
| `npm run lint` · `npm run format` | ESLint · Prettier (with the Tailwind class sorter).                        |
| `npm run build:spa`               | Build without prerendering (debugging only).                               |

## How it's put together

```
src/
  app/          routes, router, providers, layout, error page
  components/
    ui/         shadcn/ui primitives (button, dialog, tabs, accordion, sheet, tooltip, badge)
    reactbits/  SplitText, BlurText, CountUp, SpotlightCard, Magnet (after React Bits)
    magicui/    ShimmerButton, Marquee (after Magic UI)
    island/     DynamicIsland, the activity views, ControlCenter, IslandDemo, useIslandCycle
    sections/   Hero, TrustStrip, ScrollStory, Bento, Customise, Developer, Privacy, Stats,
                Faq, FinalCta
    common/     Navbar, Footer, Logo, DownloadButton, InstallDialog, VideoPlayer, MediaImage,
                Seo, Reveal, …
  content/      every word and number on the site (typed): site, home, features, faq,
                media, download, privacy, developers, customise, island
  hooks/        useLatestRelease, useOS, useReducedMotion, useLenis, useMediaQuery, …
  lib/          github (API client), cn, motion presets, highlight (Shiki), format, utils
  pages/        one file per route
  styles/       globals.css: the @theme design tokens, utilities and keyframes
```

- **Copy lives in `src/content/`.** Components only render it. Change a fact (exe size, test
  count) once in `content/site.ts`.
- **Design tokens live in `@theme`** in `src/styles/globals.css` (colours, radii, shadows,
  easing, blur). Components use token utilities (`bg-surface-1`, `text-fg-muted`,
  `border-hairline`), never raw hex.
- **Motion** runs under `<LazyMotion strict>`: use `import * as m from 'motion/react-m'`
  (ESLint enforces it). Reduced motion turns movement into plain fades.

### The download system

`hooks/useLatestRelease.ts` calls
`GET https://api.github.com/repos/icedamericano16/Notchly/releases/latest` once per session
(cached in `sessionStorage`) and picks the files using the name patterns in
`content/download.ts` (`assetPatterns`: the Inno Setup `…setup.exe` first, `.msix` as a
second option). The version comes from the tag, then the release name, then the file name.

- No release, no installer, API error or rate limit: the button still works. The install
  dialog links to GitHub Releases and shows build-from-source steps.
- Not on Windows: the button becomes **Send link to my PC** (copies the download page URL).
- The SHA-256 on `/download` is GitHub's own `digest` for the asset.

## Swapping media

All screenshots and videos are listed in **`src/content/media.ts`**, and files live in
**`public/media/`**.

**Real app captures** (`public/media/app/`, listed as `appCaptures`) are cut-outs of the
notch taken with `notchly --demo`: the hero frame and the "hover the notch" install step
show them on a neutral desktop. To add more, capture the top of the screen while
`notchly --demo` runs, cut the notch out of its background (transparent PNG), then run
`node scripts/to-webp.mjs <folder> public/media/app` and list it in `appCaptures` with its
pixel size (captures are scaled against a 1920-px-wide screen).

Until the remaining images are captured, their entries point at labelled placeholders
(`public/media/placeholders/*.svg`, generated by `node scripts/make-placeholders.mjs`).

1. Record with `notchly --demo` (it cycles every state and pop-up).
2. Export images as **AVIF + WebP** (e.g. `install-1.avif`, `install-1.webp`) and
   videos as **WebM + MP4** plus a poster image, into `public/media/`.
3. In `media.ts`, point the entry at the files, set the real `width` / `height`, and delete
   `placeholder: true`:

   ```ts
   {
     kind: 'image', id: 'install-1',
     caption: 'Step 1: run the installer', alt: '…',
     width: 1200, height: 750,
     src: { avif: 'media/install-1.avif', webp: 'media/install-1.webp', fallback: 'media/install-1.webp' },
   }
   ```

   For the hero video (`heroVideo`): set `poster` and `sources: { webm, mp4 }` and delete
   `placeholder` (the frame then plays the video instead of the captures). It only
   downloads when near the viewport, plays while visible and pauses offscreen.

Images get explicit sizes (no layout shift) and lazy loading below the fold.

The social image (`public/og.png`, 1200×630), the PNG icons and the grain tile are rendered
from `scripts/*.html` by `node scripts/render-png.mjs` (uses a local Edge or Chrome).

## SEO and performance

- Every route is **prerendered** at build time (`src/entry-server.tsx` +
  `scripts/prerender.mjs`): crawlers and visitors get full HTML, which then hydrates. The app
  script starts after the first paint.
- Per-route title, description, canonical, Open Graph and Twitter tags (`components/common/Seo.tsx`),
  `SoftwareApplication` JSON-LD on the home page, `sitemap.xml` and `robots.txt` generated
  at build time, web manifest and icon set.
- The site origin comes from `VITE_SITE_URL` (default
  `https://icedamericano16.github.io/Notchly`, set in `vite.config.ts`). For a custom
  domain, build with `VITE_SITE_URL=https://your.domain npm run build` or put it in a
  git-ignored `website/.env.local`.
- Heavy parts load on demand: the scroll story, the sections below the fold, Shiki,
  the install dialog, the mobile menu, Lenis. Decorative loops and smooth scrolling start
  on the first interaction and pause offscreen. Only `transform` and `opacity` animate.

## Deploy

All three options build with `npm run build` and publish `website/dist`.

**Vercel:** import the repository, set **Root Directory** to `website`. `vercel.json`
does the rest (static output, caching headers; unknown URLs get the prerendered 404 page).

**Netlify:** new site from Git, **Base directory** `website`. `netlify.toml` sets the
build command, publish folder and caching.

**GitHub Pages:** `.github/workflows/website.yml` builds on every change under `website/`.
Deploying is manual so it never replaces the current Pages site by surprise:

1. Repository › Settings › Pages › **Source: GitHub Actions**.
2. Actions › **Website** › Run workflow (deploy ticked).

It builds with `BASE_PATH=/Notchly/` and copies `docs/privacy.html` (and any Google
verification file) into the output, so the privacy-policy URL used for Google OAuth
verification keeps working.

## Accessibility

Semantic landmarks and headings, a skip link, visible focus rings, `aria` on the island
(a real button opens and closes it; Escape and a tap outside close it), working tab and
radio groups, labelled switches, a pause button for the island demo, alt text everywhere,
and text contrast of at least 4.5:1 (`text-fg-faint` is only used for large or decorative text).
